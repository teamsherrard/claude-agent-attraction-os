# Carousel Craft — part of the aa-carousel-design skill

Read in full before building any carousel. The mechanics are the ones proven in the sister suite's
social-graphics skill; the audience is agents, the copy comes locked from the Short-Form system.

## THE DOC PATH — THE COPY IS LOCKED (read whenever the carousel doc exists)

The Short-Form system writes one doc per carousel, `[YYYY-MM-DD] · Carousel · [Short Topic]`, in
`03 · Content/Graphics/[YYYY-MM · Month]/`. Its blocks and what each becomes:

| Doc block | Builds this |
|---|---|
| THE BRIEF (type · pillar · for whom · story used · rung + keyword) | your plan: which structure, which CTA rung, whether a LinkedIn reframe exists |
| COVER (slide 1) | the hook cover — the agent's problem or the surprise, verbatim |
| SLIDE 2 → N−1 | one slide each, in order, header line + 1–2 lines, verbatim |
| FINAL SLIDE — the CTA | the CTA slide: one rung, the keyword where the doc puts it, the member's lockup |
| THE LINKEDIN VERSION (when written: 8–12 pages + the post copy) | the second designed set, bigger type, and the LinkedIn PDF |
| THE DESIGN BRIEF FOR DS-CAROUSEL | sizes, which slide is the hook and the CTA, the colours / fonts / feel in words, the logo rule, the brokerage line — cross-check against the Design System; the Design System wins on execution values |
| INSTAGRAM + FACEBOOK block · LINKEDIN block | the captions, verbatim, packed into the captions file |
| COMPLIANCE | the strip on the CTA slide (and the footer line where the stamp requires it) |

**THE VERBATIM LAW.** The Short-Form system wrote the copy in the member's voice and read it back
slide by slide against the cardinal rules. Use its words: the cover, every header, every support line,
the CTA, the captions. You may break a line for fit or cut a support line that overflows its zone —
never change meaning, numbers, or voice; never add a slide; never drop one; never write a new hook.
When a doc line will not fit at the text-size floor, cut to its first clause and tell the member which
slide was cut so they can shorten it in their Short-Form system if they prefer.

**Self-verify:** walk the doc top to bottom and tick every block off against the board — a slide with
no matching block, or a block with no slide, is a fail. The member should be able to read the doc and
the slides side by side and see the same words in the same order.

## THE THREE STRUCTURES (the doc decides; you render)

- **"Why I Left My Brokerage" — Story (8–9 slides):** cover (the moment, in the agent's words) → where
  I was → the wall → what I believed then → the turn → what I built → what's different now → who I help
  now → CTA (save/share, or "DM me 'call'"). **The former brokerage is never named** — "a franchise", "an
  independent", "a big team". If a doc line names one (it shouldn't), render the type and tell the
  member. Not one negative word about it or anyone there; the post is about the problem, never the
  company. No compensation anywhere — why they left is a problem, where they went is "the vehicle".
- **Pain-point — Authority / Perspective (8 slides):** cover (the pain, as the agent says it) → why it
  happens → what most agents do → the fix in three steps → what it looks like fixed → CTA (the keyword).
- **Myth-busting — Perspective (8 slides):** cover (the myth, verbatim as agents say it) → why people
  believe it → the truth → the evidence (three slides) → what to do instead → CTA. A myth about the
  business, never about a named brokerage. **The myth/truth reveal:** the myth slide in a muted or greyed
  treatment with a plain "MYTH" tag; the truth slide in full brand accent — never both on one slide; the
  swipe IS the reveal.
- **"Why Join Me" — the Week 2 five-slide quick win (no doc yet):** cover (the "I know what it's like
  to…" line — the past, as the hook) → the transformation → the mission → the value ("you don't just get
  [the brokerage]; you also get…" — outcomes only) → the vision + CTA ("Book a call with me" / "DM me
  'call'"). Every line comes from the Brain Book's Your Model, Positioned chapter (the why-join-me block);
  you compress five parts into five headlines and one support line each — the member's own words, cut,
  never rewritten.

## SIZES & PLATFORMS (one build, every platform)

- **Slides — 1080×1350 (4:5 portrait), the default the Short-Form brief names;** square 1080×1080 via
  the tweak. EVERY slide the exact same size. Keep key text ~100px inside the edges.
- **GRID-SAFE COVER (Instagram):** the profile grid shows a 3:4 tile and crops ~34px off each side of a
  4:5 post — keep the cover's headline, any face, and the footer inside the central ~1012px width AND
  inside the central 1080×1080 so the tile never beheads the hook.
- **THE LINKEDIN VERSION LAW.** LinkedIn has no swipe carousel — carousels post there as a PDF
  "document post", and team leaders and broker-owners live on LinkedIn. So EVERY carousel ships a
  LinkedIn PDF: when the doc carries THE LINKEDIN VERSION (the leader reframe: retention, the exhaustion
  of carrying a team, "two steps back to take twenty forward"), design it as its own set — 8–12 pages,
  one idea per page, type a size up — and export it as the PDF with the doc's LinkedIn post copy. When
  the doc has no reframe, the same slides export as the PDF with the doc's LinkedIn caption (or, absent
  one, the Instagram caption without hashtags). Zero redesign either way; a whole second audience.
- **THE STORY ECHO.** Every carousel also ships ONE story-size frame (1080×1920): the cover re-laid-out
  for vertical with breathing room top and bottom, key text out of the top and bottom ~250px, plus a
  designed tinted plate (never a dashed box) where the member drops the "See full post" link sticker.
  Feed post + story push, same day, one build. Skip only if the storyEcho tweak is off.
- Render each slide as its own frame, in order, labelled ("Slide 1 — Cover", …, "Story echo").

## THE COVER (the post lives or dies here)

The hook is the doc's — you render it. Run the **COVER TEST** on the render, not the words:
1. **Stakes** — the agent's problem or the surprise reads at a glance, not a logo-only cover, not
   "swipe →" as the whole slide.
2. **Specificity** — the doc's number, stage, or named type of agent is the biggest text, not a
   decoration.
3. **Curiosity gap** — the payoff is on a later slide; if the layout accidentally shows it (a visible
   slide-2 fragment in a seamless flow), fix the flow.
4. **Thumbnail legibility** — the cover headline is the biggest text in the whole set and still reads at
   grid-thumbnail size (~130px wide). If it wouldn't, set it bigger.
The member's cut-out or headshot on the cover lifts performance on Story covers; on pain-point and
myth-busting covers the words lead and the face is small or absent.

## THE VALUE SLIDES (variety inside one template)

- **One idea each, large readable type, minimal.** Header + one short line or ≤3 one-line bullets; the
  doc already obeys this.
- **LAYOUT QUOTA:** a carousel of 6+ slides uses at least 3 DIFFERENT value-slide layouts — a big-number
  or stat slide, a quote or pulled-line slide, a photo slide (with a scrim), a clean text slide, a
  two-column then/now slide, a numbered-step slide — and no two consecutive value slides share a layout.
  **THE SAME-CARD TEST:** if slide 4 is slide 3 with different words, redesign one of them.
- **MID-SWIPE RE-HOOK:** in carousels of 7+ slides the middle slide (4 or 5) earns the next swipe —
  the doc's turn, the surprising line, the "what I built" reveal — give it the strongest layout of the set.
- **Persistent footer on EVERY slide:** the member's @handle + the booking link or site (and the small
  mark) in a reserved bottom band, so contact is present no matter which slide gets screenshotted; the
  compliance strip rides the footer where the stamp requires it on every slide, else on the CTA slide.
- **RESERVE ZONES — nothing overlaps.** The footer owns the bottom band; the headline and support sit
  above it with a real gap; the swipe cue owns its corner; the cut-out never touches a word. If anything
  collides or touches, the slide is wrong.
- **One focal point per slide**, generous spacing; where text sits over a photo, a dark gradient scrim.
- **Never repeat one photo** to fill slides; brand grounds, the toolkit's devices, and the oversized
  mark carry the value slides.
- **Optional SEAMLESS FLOW (the premium flex):** once the series template is locked, a background
  device — a brand line, an arc, a colour band — may run continuously across slide boundaries so
  swiping feels like panning one wide canvas. Background only; headlines, footers, and the swipe cue
  stay per-slide and inside margins; every slide still works alone in the grid; the flow never carries
  text across a cut. A tweak, never forced on a first run.

## THE CTA SLIDE

One clear action — the doc's rung, exactly: *"Comment PARTNER and I'll send you what I built"* · *"Save
this. Send it to an agent who's where I was."* · *"DM me 'call' if this is you."* — with the member's
lockup: the mark, the headshot, the @handle, the booking line. The keyword in caps as the doc writes it
(the Short-Form system reads that exact word). Never the model, never a number, never "join
[brokerage]". The compliance strip here always.

## COPY DISCIPLINE ON THE RENDER

- **Headline:** the doc's header line (~3–8 words); **support:** the doc's 1–2 lines or ≤3 one-line
  bullets. A slide reads in ~3 seconds.
- **TEXT-SIZE FLOOR: nothing below ~36px on the 1080 canvas** (footers and source lines ~28px minimum).
  If a doc line must shrink under that to fit, the slide has too many words — cut to the first clause
  (and say which slide), never shrink.
- Bullets, not sentences, for lists; spell every name, handle, and link correctly; contact in full plain
  text, never a redacted token.

## INFOGRAPHIC RULES (whenever a slide carries a number)

A pain-point's sourced number, a myth-busting evidence slide, a proof line with a figure — any slide
that carries a number follows the infographic anatomy, not a decorated digit:
1. **The slide's title is a claim, not a label** (the doc's header line already is).
2. **ONE hero number**, numerals in the heading face at 3–5× body size, the unit smaller beside it, one
   short context line under it. Never two numbers fighting.
3. **Supporting blocks only if the doc has them** — up to 3 stat tiles OR one simple chart, never both.
4. **Source + date line — MANDATORY.** Small, quiet, always: "Source: [what the doc cites] · [Month
   YYYY]". A number with no source is a rumour that exposes the member; a doc number WITHOUT a source
   gets the member's own label ("my production, 2025" / "our group, as of [date]") only if the doc gives
   it — otherwise the number comes off the slide and you say so.
5. **CHART RULES:** bars compare, lines show trends — nothing else; max 5 bars or points; values labelled
   ON the chart; bars start at zero; no 3D, no pies beyond 3 slices, no double axes; brand colours with
   the accent on the ONE data point the slide is about.
6. **NUMBER CRAFT:** round as the doc rounds; direction arrows in the accent treatment; every figure
   VERBATIM from the doc — never invented, never recombined into a claim the doc didn't make; never a
   compensation, split, cap, stock, or income figure, no matter how it is sourced.
**ONE-GLANCE TEST:** cover the supporting blocks — the title + the hero number tell the story alone.

## CAPTIONS & ALT TEXT (deliver alongside the slides)

The captions are the doc's: the **Instagram + Facebook** block (the caption, 3–5 hashtags, the FB tweak)
and the **LinkedIn** post copy (150–200 words, a first line that stands on its own, 0–3 hashtags, the ask
= "message me" or the keyword typed in a reply). Pack them verbatim into `[slug]-captions.md` and show
them in chat. Add what the doc doesn't carry:
- **Alt text, one line per post** ("Carousel: why Taylor left a franchise brokerage in year three, and
  what she built after") — the member pastes it into Instagram's alt-text field; it makes the post
  accessible and searchable.
- **The first-line check:** Instagram cuts the caption after ~125 characters; if the doc's first line
  runs past it, say so once — never rewrite it.
- **The LinkedIn hand-off line, on every carousel:** *"LinkedIn version: upload `[slug]-linkedin.pdf`
  as a document post with the LinkedIn copy below."*

## SERIES MODE — one template, every week (what makes the feed look branded)

- **First run: lock the series template.** The cover treatment, the value-slide system, the footer, the
  accent use, and the CTA slide established on the first carousel ARE the member's carousel template —
  built from the Design System's tokens and the toolkit's devices, so it already matches the brand kit.
  Recap it in one line when presenting ("Your series template: dark cover, brass accent, cream value
  slides, headshot CTA") and hand them a copyable **SERIES TEMPLATE CARD** — 5 plain lines: cover look ·
  value-slide layouts · colours/theme · footer contents · CTA slide — to keep in the Brand HQ project.
- **Name the series** when the member wants one — a weekly carousel performs better as a recognizable
  franchise ("Agent Attraction Notes — No. 7"), same small cover treatment every week.
- **Every later run: same system, new content.** A new doc pours into the locked template; only the
  value-slide layouts vary as the content demands. A later run in a fresh chat rebuilds the system from
  the card; if you can't see the first carousel OR the card, ask for the card — never guess from memory.
- **Refresh on request only** ("refresh my carousel style"): evolve the template once, confirm, lock the
  new version.
- **Quick edits welcome:** change ONLY what's asked ("tighter cover", "swap slide 4's layout", "brighter
  CTA"); never regenerate the set.

## LANGUAGE — DESIGN IN THE BRAND'S LANGUAGE(S)

The slides are designed in the member's brand language(s) from the Design System; the doc arrives in
that language. If the doc is written in a different language than the brand, ask which language this
post should be in before designing (they may be testing a new audience). Every fragment translates — the
swipe cue, slide labels, the "MYTH" tag, the CTA, the sticker-plate label; accents survive all-caps
headlines; numbers localized; a bilingual brand gets two matched sets, never both languages on one slide.

## CANONICAL FILE NAMES (the Short-Form system and the board read these — keep them exact)

`[slug]` = the doc's short topic, lowercase, hyphenated (`why-i-left`, `paying-for-leads`):
`carousel-[slug]-01.png` … `carousel-[slug]-NN.png` (the slides, in order) ·
`carousel-[slug]-linkedin-01.png` … (the LinkedIn set, when a reframe was designed) ·
`carousel-[slug]-linkedin.pdf` (via the Export menu — one slide per page, in order) ·
`carousel-[slug]-story.png` (the story echo) · `carousel-[slug]-captions.md` (captions + alt text + the
series template card on a first run).
