# Guide Craft — part of the aa-lead-magnet-design skill

Read in full before designing any page. The page mechanics are the ones proven in the sister suite's
guide designer; the content is locked by the Lead Magnet system; the reader is a licensed agent weighing
a move, reading on a phone.

## THE DOC PATH — THE CONTENT IS LOCKED (read whenever the magnet doc exists)

The Lead Magnet system writes **`Lead Magnet — [Guide Name]`** in the campaign folder
`03 · Content/Guides/[YYYY-MM-DD · Guide Name]/`, and `lm-design` writes **`Design Brief — [Guide
Name]`** beside it. When the doc is uploaded or read through the connector, **it is the guide.** Design
it; never re-author it.

**THE VERBATIM LAW.** The doc's words are the guide's words — every page title, every bullet, every
number, the source notes in parentheses, the "verify current" line on page 1, the "last updated" date,
the close. You may split a long page across a spread or break a line for fit; you never change meaning,
numbers, voice, or order; you never add a chapter, a welcome page, a checklist, or a tip the doc
doesn't have ("nothing added, nothing cut, no punching up" — the brief's rule); you never "punch up" a
line.

**THE STRUCTURE MAP:**

| Doc block | Becomes |
|---|---|
| THE PROMISE | the **cover** — the title exactly, the subtitle = the promise line exactly, "By [Name], [Brokerage as required]", "Last updated [Month YYYY]" |
| `── PAGE N - TITLE ──` blocks | **one designed page each, in the doc's order, the title verbatim** as the page header |
| HOW [FIRST NAME] HELPS NEXT | the **closing page** — the doc's close verbatim, the member's headshot, the booking link as the ONE button, the social handles; nothing else on the guide gets a button |
| ▸ NEXT — assets to gather | what to ask for (logo · headshot · photos with the organization) — nothing else |
| ▸ COMPLIANCE | the compliance stamp — on the cover's bottom strip, in every page's footer, and in full on the closing page |

**Page count on this path:** the cover + the doc's body pages (the comparison guide is 7, plus the
optional 8th story page — only when the doc has it; never a placeholder page) + the closing page —
typically 9–10. No contents page, no welcome page, no added checklist: page 7 IS the checklist.

**Self-verify:** walk the doc top to bottom and tick every block off against the board — a doc page
with no frame, or a frame the doc doesn't have, is a fail. The member should read the doc and the guide
side by side and see the same words in the same order.

## THE COMPARISON GUIDE — the first magnet, and the layout it wants

The Honest Brokerage Comparison Guide is locked as every member's first magnet: a factual, cited,
dated comparison of brokerage MODEL TYPES — never a ranking, never a named brokerage other than the
member's own, "honest" meaning transparent about trade-offs including the member's own. Its seven pages
and how each wants to be laid out:

1. **Why this guide exists (and what it isn't)** — the framing page: a calm opener with the "what it
   is not" lines as a quiet designed list (not a ranking · not a pitch · not legal or financial advice ·
   written by a working agent and leader · dated · plans change, verify current). The "verify current"
   line sits where a reader can't miss it.
2. **How to read any brokerage model** — the five parts (compensation · additional income · equity ·
   support · operations) as five labelled tiles or a five-row key; structure, not numbers.
3–6. **The four model pages — ONE IDENTICAL LAYOUT.** Cloud brokerage with revenue share · franchise
   split · flat-fee / 100% · independent or local brokerage and the local team — each in the SAME five
   blocks (how it works · who it tends to fit · what to love · the honest trade-off · the question to
   ask), the same block sizes, the same type sizes, the same length. **A longer or bolder page for the
   member's own model reads as a pitch** — the brief says so; the member's own model page carries one
   quiet "(mine)" marker and nothing else that differs. The member's model sits first or last, never in
   the middle. Source notes stay in their parentheses, set small but legible.
7. **The questions to ask any brokerage or sponsor** — the checklist page: every question with a real
   empty checkbox square, grouped as the doc groups them, the two closing questions (*"show me the
   training I'd get, today"* · *"show me an agent like me you've helped"*) given weight; the page carries
   its own compact footer (the member's name · booking link · the mark) because it gets screenshotted
   and shared detached from the guide. **THE SCREENSHOT TEST:** the whole page, legible, in one phone
   screenshot.
8. **(Optional) What I'd tell myself** — the member's own switch story, "a franchise" / "an independent",
   never a name; a photo-led page when a real photo exists; omitted entirely when the doc omits it.

**Second-campaign guides** (the switching checklist, questions to ask a sponsor, the rev-share
explainer, the 90-day plan, the member's system, the leader's switching guide, a prompt list) arrive
with their own PAGE blocks — same map, same laws, same closing page; a checklist-shaped page gets the
checkbox treatment; a template-shaped page (the 90-day plan) gets real fill-in rows.

## SIZES (a real multi-page PDF)

- **US Letter portrait, 2550×3300 px** (A4 via tweak when the brief's Locale says A4); every page its
  own clearly labelled frame, in order ("Cover", "Page 1 — Why this guide exists", …, "Closing page");
  content inside a safe margin (~0.5–0.75 in); nothing touching an edge; nothing sitting outside the
  frame edge to be clipped when it becomes a PDF page.
- **Phone-readable at 100%:** body ≥ 11pt (the brief's floor), contrast that passes on a phone, headers
  that read at a glance when the PDF opens small.
- Build it as one cohesive document: the same grid, margins, type scale, accent, page numbers, and the
  running footer on every page.

## BUILD ORDER — STAGED, WITH CHECKPOINTS (a 10-page guide must never die half-rendered)

1. **Stage 1 — the cover + page 1 + ONE model page.** These three lock the template every later page
   inherits (grid, margins, type scale, accent, the footer with the compliance stamp). CHECKPOINT: all
   three rendered fully, top to bottom; the cover passes the thumbnail test; the model page's five blocks
   fit at ≥ 11pt with room to spare — because the other three model pages must match it exactly.
2. **Stage 2 — the remaining model pages, then page 2 and page 7**, in batches of 3–4. CHECKPOINT after
   each batch: every page complete, on the locked template; the four model pages identical in layout
   and length.
3. **Stage 3 — the optional story page, the closing page.** CHECKPOINT: the booking button is the only
   button in the guide; the compliance stamp in full.
4. If ANY page comes out incomplete or off-template, fix THAT page before adding new ones.
**THE TURN NEVER ENDS AT A CHECKPOINT** — a stage that passes is followed by the next in the same
response.

## THE COVER (it sells the opt-in — it reappears as the 3D mockup)

The title exactly as the doc gives it, the single largest element (at least 3× body size; the doc's
title is short by design — if it runs long, keep the wording and split it into a short dominant line +
the subtitle), the subtitle = the promise line, "By [Name]" with the brokerage as compliance requires,
"Last updated [Month YYYY]" — keep it, the guide is dated on purpose. A brand field, the toolkit's
texture, the oversized mark device, or a real photo of the member or their organization (with a scrim)
— never a stock person, never a generated face, never another brokerage's logo, never stars, never
"best", never a ranking word. **THE THUMBNAIL TEST (mandatory):** at ~150px wide the title reads and the
brand is recognizable — or rebuild the cover BEFORE any other page. The compliance strip rides the
cover's bottom edge as the thinnest line.

## DESIGN CRAFT — MAKE IT LOOK PUBLISHED (not a Word doc)

- **One cohesive template across every page:** consistent margins, a clear type scale (big page
  headers, body 11–12pt, an eyebrow above headers — "PAGE 3 · THE MODELS"), a single accent, page
  numbers, the running footer (the guide's title or the member's name + the compliance stamp).
- **Generous whitespace and strong hierarchy:** one dominant idea per page, copy in short sections,
  bullets, and pull-quotes; a wall of text fails the craft bar.
- **LAYOUT QUOTA (enforced where the doc allows it):** the four model pages are identical by rule, so
  the variety lives on pages 1, 2, 7, the story page, and the closing page — at least THREE visibly
  different layouts across those (a full-width opener, a tiled key, a checklist page, a photo-led page, a
  closing page with the headshot and the button) — same grid, same type scale, different rooms.
- **Real visuals only:** the member's headshot on the closing page (and the story page when it fits),
  real photos of the organization only when supplied (never stock people, never another brokerage's
  event), the toolkit's devices, clean icons in one style. Charts only if the doc carries sourced
  numbers (bars from zero, values on-chart, source and date beside it).
- **Nothing overlaps; nothing is cut off.** Every element gets its own space; text never runs under a
  photo or off the page; every page complete on its own.
- **The brand throughout:** the Design System's colours, fonts, logo treatment, and direction — the
  leader palette, visibly distinct from the brokerage's own; the brokerage's mark only where the brief's
  compliance line puts it, at the size it says.

## THE CLOSING PAGE (the only place the next step lives)

The doc's HOW [FIRST NAME] HELPS NEXT, verbatim: what the member gives agents who partner with them (as
the doc wrote it — outcomes), the brokerage line, one real proof point if the doc carries one, and the
one next step. The **booking link as the ONE button** ("Book a call with me" — the Book's primary CTA
as the doc words it), the social handles as quiet text links, the member's headshot in the Design
System's frame, the compliance stamp in full with the required disclaimer verbatim. No second CTA, no
QR code the member didn't ask for, no "join [brokerage]", nothing about compensation.

## LANGUAGE — THE GUIDE SPEAKS THE BRAND'S LANGUAGE(S)

Designed cover-to-back in the member's brand language(s) from the Design System; the doc arrives in
that language — if it doesn't, confirm which language the finished guide should be in before designing.
Native copy throughout; numbers and dates formatted as the locale writes them; the regulated title with
the member's name where the region has one (Québec: "courtier immobilier" / "courtière immobilière",
never a literal translation); accents surviving headers and all-caps; a bilingual brand gets two guides,
one per language, same design — matching their funnel pages.

## REFRESH MODE — UPDATE, DON'T REBUILD

Brokerage plans change, so the guide is dated and will be refreshed. When the member returns with a
refreshed doc ("update my guide for [Month YYYY]"), change ONLY the pages whose words changed — a
mechanic, a source note, the "last updated" date, a new photo — keep every other page identical, show
the changed pages, and re-export the PDF under the SAME file name so the funnel's download button keeps
working. Never a redesign on a refresh.

## CANONICAL FILE NAMES (the funnel and the Lead Magnet system read these — keep them exact)

`[slug]` = the Guide Name, lowercase, hyphenated (`honest-brokerage-comparison-guide`):
`guide-[slug].pdf` (the whole guide, via the Export menu — the exact file the funnel bundles as
`assets/guide.pdf`) · `guide-cover.png` (the flat cover, 1700×2200) · `guide-mockup.png` (the 3D shot,
2400×2400, transparent) · `guide-mockup-square.png` (1080×1080) · `guide-mockup-story.png` (1080×1920)
· `guide-notes.md` (the hand-off text).
