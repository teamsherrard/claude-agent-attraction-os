# Guide Craft — part of the aa-lead-magnet-design skill

Read in full before designing any page. The page mechanics are the ones proven in the sister suite's
guide designer; the content is locked by the Lead Magnet plugin (the words, in the guide file) and by
chapter 4 of the Week 3 Kit (what to build); the reader is a licensed agent weighing a move, reading on
a phone.

## THE GUIDE PATH — THE CONTENT IS LOCKED (read whenever the guide file exists)

The Lead Magnet plugin writes the guide — **`Lead Magnet — [Title]`**, in the member's Guides folder
(`03 · Content/Guides/`) — as a real guide: a cover page, one page per section with a Title Case heading,
the closing page, the back page, its elements already on the page. **Chapter 4 of the Week 3 Kit** says
what to build (THE IDEA YOU SAID YES TO · THE OUTLINE with a `· picture:` line per page · `DESIGN BRIEF —
[GUIDE NAME]`). There is no separate brief document. When the guide is uploaded or read through the
connector, **it is the guide.** Design it; never re-author it.

**THE VERBATIM LAW.** The guide's words are the guide's words — every page title, every bullet, every
number, the source notes in parentheses, the "verify current" line on page 1, the "last updated" date,
the close, and the text after every labelled line. You may split a long page across a spread or break a
line for fit; you never change meaning, numbers, voice, or order; you never add a chapter, a welcome
page, a checklist, or a tip the guide doesn't have ("nothing added, nothing cut, no punching up" —
chapter 4's rule); you never "punch up" a line. **A label never prints** — in an older guide written as
labelled lines, the word before the colon is an instruction to you and what follows it is the member's
copy; in the rendered guide the element itself (the large quote, the shaded box, the box list, the
blanks, the speech line, the small grey text) tells you what it is.

**THE STRUCTURE MAP** (the rendered guide first; an older guide written as labelled blocks in brackets):

| Guide part | Becomes |
|---|---|
| The cover page — the title, the subtitle, "By [Name], [Brokerage as required]", the three hook lines, "Last updated [Month YYYY]" when dated (THE PROMISE: `Title:` · `Subtitle:` · `Byline:` · `Hook:`) | the **cover** — the title exactly as the single largest element, the subtitle, the byline, the three hook lines set as three short lines, "Last updated" when the guide is dated — chapter 4's `The cover:` |
| The opening page — the first Title Case heading (`── PAGE 1 - TITLE ──`) | the **opening page** — the title verbatim as the header, the context as readable body, its large quote and picture if any, and the two "how to use this" lines as the page's closing strip |
| Each body page — one Title Case heading per section, in order; chapter 4's `Pages:` outline lists them one per bullet (`── PAGE N - TITLE ──`) | **one designed page each, in the guide's order, the title verbatim** as the page header; every element its design element (the elements table below); the picture from the outline's `· picture:` line |
| The "what to do next" page — the last body page (`── PAGE N - WHAT TO DO NEXT ──`) | the **screenshot page** — the five-line box list with real boxes, the next-step strip, any call to action as a quiet strip; its own compact footer |
| The closing page — "How [First name] helps next" (HOW [FIRST NAME] HELPS NEXT) | the **closing page** — the close verbatim, the proof line if any, the member's headshot, the ONE button (the booking link, or the contact the kit names), the social handles; nothing else in the guide gets a button |
| The back page (THE BACK PAGE) | the **back page** — contact · socials (if any) · "Last updated" (if dated) · the compliance line in full — set quietly, the mark small, the leader palette |
| The compliance line (▸ COMPLIANCE on an older guide; the kit's closing line) | the compliance stamp — on the cover's bottom strip, in every page's footer, and in full on the back page |

**Page count on this path:** the cover + the guide's pages (6–10: the opening page, 4–8 body pages, the
"what to do next" page — chapter 4's `Pages:` outline counts them; a comparison guide's body is 6–7, its
story page only when the guide has it; never a placeholder page) + the closing page + the back page —
typically 9–13. No contents page, no welcome page, no added checklist: the guide's box lists ARE the
checklists.

**Self-verify:** walk the guide top to bottom and tick every page off against the board and against
chapter 4's outline — a guide page with no frame, or a frame the guide doesn't have, is a fail. The
member should read the guide file and the PDF side by side and see the same words in the same order.

## THE ELEMENTS — each becomes a design element (never a printed label)

The rendered guide shows its elements on the page; an older guide marks them with labelled lines — two
forms: an **inline** label carries its text on the same line; a **list** label stands alone and its items
follow as `•` lines (one per item, until a blank line or the next label). Every one is optional in the
guide; when it is there, it renders like this — exactly as chapter 4's `The pages:` line says:

| In the guide (the older label) | Renders as |
|---|---|
| the cover page (`Title:` · `Subtitle:` · `Byline:` · `Hook:`) | the cover (above) |
| the two "how to use this" lines on the opening page (`How to use this:`) | the opening page's closing strip — two short lines in a quiet band |
| a quote set large (`Pull quote:`) | the page's one line set large — display size, the accent, generous air; the sentence a reader would screenshot |
| a shaded box (`Callout:`) | a callout panel — a tinted box or a rule-bound aside, the brand's radius, body size |
| a box list (`Checklist:`; 3–7 items, the next-step page's is 5) | real empty checkbox squares, one per item, grouped as the guide groups them; the tweak decides boxes vs numbered boxes |
| blanks — `____` fill-in lines (`Template rows:`) | fill-in rows a reader can write on — a row label and a ruled line per blank, phone-legible at 100% |
| a shaded speech line (`Script:`; `Me:` / `Agent:` for two voices) | message bubbles (two voices as two sides) or a script card — the tweak decides; the words verbatim |
| small grey text (`Source:`) | a footnote line at the page's foot — small (≥ 9pt), legible, the number it cites marked |
| the picture line — chapter 4's `· picture:` for the page, or an `Image idea:` line in the guide | the page's visual, built from the direction: a drawn mockup of the sheet with the one question circled · the toolkit's phone with the three texts on it · the weekly review half filled in · a real photo with a scrim when one exists — never stock, never a generated face; **the text itself never prints** |
| the next-step line (`Next step:`) | the page's closing strip — one line in a band at the foot of the page, consistent across every page that has one |
| a call to action (`Call to action:`) | on a body page and on the "what to do next" page: a quiet strip (the words, no button, no link — the guide wrote "the link's on the last page"); on the closing page: the ONE button — the booking link, or the contact the kit names |
| the proof line on the closing page (`Proof:`) | a proof row — the consented result set as a quiet quote-and-name line beside the headshot |
| the back page's lines (`Contact:` · `Socials:` · `Last updated:` · `Compliance:`) | the back page |

One element style for each across the whole guide — the template locks them in stage 1.

## THE SHAPES — the layout each wants

The member's Lead Magnet plugin wrote one of six shapes from their own offer; the guide's pages (and
chapter 4's `Why this one:`) say which. Same map, same labels, same opening page, same "what to do next" page, same closing page and back
page for every one of them:

- **The member's system guide** — an at-a-glance page (the steps in order as designed rows or a
  checklist; the screenshot test), one page per step with the template handed over set as a real sheet
  (template rows) and the script as bubbles, a first-week page, a what-good-looks-like page when the guide
  has one.
- **The checklist** — the checklist pages with a real empty box per item, grouped; the explaining pages;
  the before-and-after timeline as fill-in rows.
- **The plan or template** (the 90-day plan) — real fill-in rows on every week page and on the review
  page; activity targets exactly as the guide states them, never a figure of your own.
- **The questions guide** — the question pages as checklists (a box per question), "what a good answer
  sounds like" set smaller beside each; the two closing questions as a script card.
- **The mini-course outline** — one lesson per page, the template in full, the "after this you can" line
  as the page's eyebrow; the prompt or script page as a script card.
- **The fair comparison guide** — the layout below.

### The comparison guide (when it is the shape)

A factual, cited, dated comparison of brokerage MODEL TYPES — never a ranking, never a named brokerage
other than the member's own, "honest" meaning transparent about trade-offs including the member's own.
Its pages and how each wants to be laid out:

1. **PAGE 1 — Why this guide exists (and what it isn't)** — the opening page: a calm opener with the
   "what it is not" lines as a quiet designed list (the guide's `Checklist:` — not a ranking · not a pitch ·
   not legal or financial advice · written by a working agent and leader · dated · plans change, verify
   current). The "verify current" line sits where a reader can't miss it; the `How to use this:` strip
   closes it.
2. **How to read any brokerage model** — the five parts (compensation · additional income · equity ·
   support · operations) as five labelled tiles or a five-row key; structure, not numbers.
3–6. **The four model pages — ONE IDENTICAL LAYOUT.** Cloud brokerage with revenue share · franchise
   split · flat-fee / 100% · independent or local brokerage and the local team — each in the SAME five
   blocks (how it works · who it tends to fit · what to love · the honest trade-off · the question to
   ask), the same block sizes, the same type sizes, the same length. **A longer or bolder page for the
   member's own model reads as a pitch** — the rule in chapter 4; the member's own model page carries one
   quiet "(mine)" marker and nothing else that differs. The member's model sits first or last, never in
   the middle. `Source:` lines stay as footnotes, set small but legible. The mid-document `Call to
   action:` the guide put on the member's own model page renders as the same quiet strip at the same size
   on that page only.
7. **The questions to ask any brokerage or sponsor** — the checklist page: every question with a real
   empty checkbox square, grouped as the guide groups them, the two closing questions (*"show me the
   training I'd get, today"* · *"show me an agent like me you've helped"*) given weight; the page carries
   its own compact footer (the member's name · booking link · the mark) because it gets screenshotted
   and shared detached from the guide. **THE SCREENSHOT TEST:** the whole page, legible, in one phone
   screenshot.
8. **(Optional) What I'd tell myself** — the member's own switch story, "a franchise" / "an independent",
   never a name; a photo-led page when a real photo exists; omitted entirely when the guide omits it.
Then the guide's `WHAT TO DO NEXT` page (the five parts of any model as the five-line checklist), the
closing page, the back page.

**Other shapes Mike names** (the rev-share explainer, the leader's switching guide, a prompt list, a
script) arrive with their own PAGE blocks — same map, same labels, same closing page; a checklist-shaped
page gets the checkbox treatment; a template-shaped page gets real fill-in rows; a script page gets the
bubbles or the card.

## SIZES (a real multi-page PDF)

- **US Letter portrait, 2550×3300 px** (A4 via tweak when chapter 4's `What to build:` says A4); every page its
  own clearly labelled frame, in order ("Cover", "Page 1 — Why I wrote this", …, "What to do next",
  "Closing page", "Back page"); content inside a safe margin (~0.5–0.75 in); nothing touching an edge;
  nothing sitting outside the frame edge to be clipped when it becomes a PDF page.
- **Phone-readable at 100%:** body ≥ 11pt (chapter 4's floor), footnotes ≥ 9pt, contrast that passes on
  a phone, headers that read at a glance when the PDF opens small.
- Build it as one cohesive document: the same grid, margins, type scale, accent, page numbers, the
  running footer, and the same element styles on every page.

## BUILD ORDER — STAGED, WITH CHECKPOINTS (a 12-page guide must never die half-rendered)

1. **Stage 1 — the cover + PAGE 1 + ONE body page.** These three lock the template every later page
   inherits (grid, margins, type scale, accent, the footer with the compliance stamp, the element styles:
   the pull quote, the callout, the checkbox, the fill-in line, the bubble, the footnote, the closing
   strip). When the guide compares models, the body page is a model page — the other three must match it
   exactly. CHECKPOINT: all three rendered fully, top to bottom; the cover passes the thumbnail test; the
   body page's elements fit at ≥ 11pt with room to spare.
2. **Stage 2 — the remaining body pages**, in batches of 3–4 (a comparison guide's model pages together).
   CHECKPOINT after each batch: every page complete, on the locked template; every element rendered as
   chapter 4's `The pages:` line says and no label printed; any model pages identical in layout and length.
3. **Stage 3 — the "what to do next" page, the optional story page, the closing page, the back page.**
   CHECKPOINT: the five-line checklist real and screenshot-legible; the booking button is the only button
   in the guide; the two earlier calls to action are quiet strips; the compliance stamp in full on the
   back page.
4. If ANY page comes out incomplete or off-template, fix THAT page before adding new ones.
**THE TURN NEVER ENDS AT A CHECKPOINT** — a stage that passes is followed by the next in the same
response.

## THE COVER (it sells the opt-in — it reappears as the 3D mockup)

The title exactly as the guide's cover page gives it (chapter 4's `The cover:`), the single largest
element (at least 3× body size; the title is seven words or fewer by rule — if it still runs long, keep
the wording and split it into a short dominant line + the subtitle), the subtitle, the byline with the
brokerage as compliance requires, the three hook lines set as three short lines in the brand's secondary
weight — the hook is
the cover's second read, under the title, never competing with it — "Last updated [Month YYYY]" when the
guide is dated (keep it, the guide is dated on purpose). A brand field, the toolkit's texture, the
oversized mark device, or a real photo of the member or their organization (with a scrim) — never a
stock person, never a generated face, never another brokerage's logo, never stars, never "best", never a
ranking word. **THE THUMBNAIL TEST (mandatory):** at ~150px wide the title reads and the brand is
recognizable — or rebuild the cover BEFORE any other page. The compliance strip rides the cover's bottom
edge as the thinnest line.

## DESIGN CRAFT — MAKE IT LOOK PUBLISHED (not a Word doc)

- **One cohesive template across every page:** consistent margins, a clear type scale (big page
  headers, body 11–12pt, an eyebrow above headers — "PAGE 3 · THE SHEET"), a single accent, page
  numbers, the running footer (the guide's title or the member's name + the compliance stamp).
- **Generous whitespace and strong hierarchy:** one dominant idea per page, copy in short sections,
  bullets, and the guide's pull quote; a wall of text fails the craft bar.
- **LAYOUT QUOTA (enforced where the guide allows it):** a comparison guide's model pages are identical by
  rule; everywhere else the labels give each page its own room — at least THREE visibly different layouts
  across the guide (a full-width opener, a tiled key or an at-a-glance page, a checklist page, a
  template page with fill-in rows, a script page with bubbles, a photo-led story page, the closing page
  with the headshot and the button) — same grid, same type scale, different rooms.
- **Real visuals only:** the member's headshot on the closing page (and the story page when it fits),
  real photos of the organization only when supplied (never stock people, never another brokerage's
  event), the toolkit's devices for `Image idea:` directions that name a phone or a screen, a drawn
  mockup of the sheet or template when the idea names one, clean icons in one style. Charts only if the
  guide carries sourced numbers (bars from zero, values on-chart, the `Source:` beside it).
- **Nothing overlaps; nothing is cut off.** Every element gets its own space; text never runs under a
  photo or off the page; every page complete on its own.
- **The brand throughout:** the Design System's colours, fonts, logo treatment, and direction — the
  leader palette, visibly distinct from the brokerage's own; the brokerage's mark only where chapter 4's
  `The brand:` line puts it, at the size it says.

## THE CLOSING PAGE AND THE BACK PAGE (where the next step lives — and the quiet end)

**The closing page.** The guide's closing page — "How [First name] helps next" — verbatim: what they now
have, what a guide can't do, what the member gives agents who partner with them (as the guide wrote it —
outcomes, in the kit's register), the brokerage line, the proof line as a quiet quote-and-name beside the
headshot if the guide carries one, and the closing call to action — **the ONE button: the booking link, or
the contact the kit names** (the guide's words on the button; chapter 5's `The call:` line when the guide
gives none), the social handles as quiet text links, the member's
headshot in the Design System's frame. No second CTA, no QR code the member didn't ask for, no "join
[brokerage]", nothing about compensation.

**The back page.** The guide's back page: the contact lines in full plain text, the socials as quiet
handles when the guide has them, "Last updated" when the guide is dated, and the compliance line in full
— the required disclaimer verbatim, the brokerage mark where chapter 4's `The brand:` places it. Quiet by design: the
brand's ground, the small mark, nothing that competes with the closing page's button. It is the last
frame of the PDF.

## LANGUAGE — THE GUIDE SPEAKS THE BRAND'S LANGUAGE(S)

Designed cover-to-back in the member's brand language(s) from the Design System; the guide arrives in
that language — if it doesn't, confirm which language the finished guide should be in before designing.
Native copy throughout; numbers and dates formatted as the locale writes them; the regulated title with
the member's name where the region has one (Québec: "courtier immobilier" / "courtière immobilière",
never a literal translation); accents surviving headers and all-caps; a bilingual brand gets two guides,
one per language, same design — matching their funnel pages.

## REFRESH MODE — UPDATE, DON'T REBUILD

Brokerage plans change, so the guide is dated and will be refreshed. When the member returns with a
refreshed guide ("update my guide for [Month YYYY]"), change ONLY the pages whose words changed — a
mechanic, a source note, the "last updated" date, a new photo — keep every other page identical, show
the changed pages, and re-export the PDF under the SAME file name so the funnel's download button keeps
working. Never a redesign on a refresh.

## CANONICAL FILE NAMES (the opt-in page and the Lead Magnet plugin read these — keep them exact)

`[slug]` = the Guide Name, lowercase, hyphenated (`the-five-step-sunday-routine`):
`guide-[slug].pdf` (the whole guide, via the Export menu — the exact file the funnel bundles as
`assets/guide.pdf`) · `guide-cover.png` (the flat cover, 1700×2200) · `guide-mockup.png` (the 3D shot,
2400×2400, transparent) · `guide-mockup-square.png` (1080×1080) · `guide-mockup-story.png` (1080×1920)
· `guide-notes.md` (the hand-off text).
